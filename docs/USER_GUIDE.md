## 串口连接

### 端口识别

端口列表由 Windows 当前提供的 COM 端口组成，按端口数字排序，并尽量保留刷新前的选择。端口项同时显示 Windows SetupAPI 提供的设备名称，例如：

```text
COM1 (通信端口)
COM5 (USB-SERIAL CH340)
```

设备说明保留 `CH340`、`CP210x` 等友好名称，只过滤 `VID_xxxx`、`PID_xxxx` 硬件编号；无法读取说明时只显示 `COMx`。实际连接始终使用 COM 端口号。

### 通信参数

| 参数 | 可选值 | 默认值 |
| --- | --- | --- |
| 波特率 | 1200、2400、4800、9600、19200、38400、57600、115200、230400、460800、921600 | 115200 |
| 数据位 | 5、6、7、8 | 8 |
| 停止位 | 1、1.5、2 | 1 |
| 校验位 | None、Odd、Even、Mark、Space | None |
| 流控制 | None、XOn/XOff、RTS/CTS、RTS/CTS + XOn/XOff | None |
| 字符编码 | UTF-8、GBK、ASCII | UTF-8 |
| DTR / RTS | 开、关 | 关 |

连接后参数区会锁定，断开后才能修改设置或切换端口。连接与断开会重置流式文本解码器；清空终端不会改变连接或解码状态。

### 设备拔插与恢复

Comet 区分用户建立的连接会话和当前物理串口句柄。通信中拔出 USB 串口后，程序释放失效句柄并继续保留连接意图；同一 COM 口重新出现时使用原通信参数自动恢复，无需再次点击连接。

恢复期间界面仍显示用户建立的“通信中”状态，不增加额外 SYS 文本。手动断开或关闭窗口会取消恢复，之后设备插回不会被 Comet 自动占用。

## 数据发送

“HEX 发送”和接收区的“HEX 显示”是两个相互独立的选项。

| 入口 | 编码与行尾 | 终端显示 |
| --- | --- | --- |
| 底部文本发送 | 解释转义，按所选编码发送，可追加无、CRLF、CR 或 LF | 开启时间戳时记录 TX |
| 底部 HEX 发送 | 解析为原始字节，忽略文本行尾设置 | 开启时间戳时记录 TX |
| 内容区键入或粘贴 | 不解释转义；真实换行按当前行尾发送 | 不做本地回显 |
| 快捷指令立即发送 | 使用该指令保存的文本/HEX模式和行尾 | 开启时间戳时记录 TX |
| 底部循环发送 | 按周期重复当前底部载荷 | 与底部发送相同 |
| 快捷指令循环发送 | 按列表快照持续逐条循环 | 与快捷指令立即发送相同 |

### 文本与转义

底部文本发送和文本快捷指令支持以下转义：

| 输入 | 数据 |
| --- | --- |
| `\\` | 反斜杠 |
| `\0` | NUL |
| `\a`、`\b`、`\f`、`\n`、`\r`、`\t`、`\v` | 对应控制字符 |
| `\xNN` | 两位十六进制字符值 |
| `\uNNNN` | 四位十六进制 Unicode 字符值 |

未知转义会保留反斜杠和后续字符。`\x` 必须跟两位十六进制数，`\u` 必须跟四位十六进制数，否则拒绝本次发送。转义完成后再按所选编码生成字节并追加文本行尾；正文和行尾都为空时不发送。

### HEX 输入

HEX 输入忽略 `0x` 前缀以及空格、Tab、换行、逗号、分号、冒号、连字符和下划线。剩余十六进制字符必须合法且数量为偶数。

HEX 模式不会自动追加 CR 或 LF，需要在数据中显式写入 `0D`、`0A`。终端中的 TX 内容按两位大写十六进制和单个空格显示。

### 内容区键入

串口连接时，点击终端内容区即可直接键入或粘贴：

- 输入内容立即按当前字符编码发送，不解释 `\r`、`\n` 等字面量。
- 真实 CR、LF 或 CRLF 统一转换为当前行尾；行尾为“无”时使用 LF，保证 Enter 能产生换行数据。
- 输入不会直接留在终端中，只有设备返回的 RX 数据才会显示。
- 内容区发送只增加 TX 字节计数，不创建本地 TX 条目。
- 光标移动、选择、复制、Delete 和 Backspace 不发送数据，也不修改只读会话。
- 无选区且内容区聚焦时显示闪烁光标；失焦或存在选区时隐藏。

### 循环发送

循环周期范围为 20–60,000 ms，默认 1000 ms。开启后等待一个完整周期再首次发送；串口不可写、载荷无效或发送失败时自动停止。

底部循环发送与快捷指令循环发送共用周期设置并互斥。底部循环运行时，编辑后的有效载荷从下一次周期开始生效；快捷指令循环在启动前生成不可变列表快照。

调度使用 Windows 高分辨率等待计时器，串口写入不依赖 UI 线程，因此终端渲染和大量 RX 不会形成持续的周期漂移。Windows 不是硬实时系统，高负载时仍可能产生短时抖动。

## 数据接收与终端

### 文本与 HEX 视图

接收字节按当前选择的 UTF-8、GBK 或 ASCII 流式解码。跨接收批次的不完整多字节字符会继续拼接，无法解码的序列显示为 `?`。

文本显示遵循以下规则：

- CRLF、LF 和 CR 各规范为一个换行。
- 非标准 `CRCRLF` 兼容为一个换行，`CRLFCRLF` 保留为两个换行。
- Tab 保留；其他 C0 控制字符显示为 Unicode 控制图形，DEL 显示为 `␡`。
- 其他 Unicode 控制字符使用 `\uNNNN` 形式显示。
- 没有硬换行的长文本按当前字体和窗口宽度软折行。

HEX 视图将每个原始 RX 字节显示为两位大写十六进制，相邻字节用一个空格分隔。接收时会同时构建完整文本会话和完整 HEX 会话；切换显示模式从对应会话更新内容，不从屏幕可见行反向转换，也不长期保留每个接收批次的原始数组。

### 时间戳与方向

时间戳默认开启，详细条目格式为：

```text
HH:mm:ss.fff  RX  内容
HH:mm:ss.fff  TX  内容
HH:mm:ss.fff  SYS  状态
```

- 开启时显示 RX、底部/快捷/循环发送产生的 TX，以及连接状态 SYS。
- 空闲间隔少于 200 ms 的连续 RX 批次保持为同一数据流，不为每个底层接收事件重复插入前缀；间隔达到 200 ms 时开始新的时间戳条目。
- 关闭后只把新 RX 写入显示缓冲；TX 和 SYS 不显示。
- 开关只影响之后产生的条目，不重写已有会话。
- 时间、方向和正文属于同一份纯文本文档，可以统一选择和复制。

### 滚动、选择与字体

终端保留自上次清空以来的完整活动模式会话，但只创建视口附近的可见行元素。滚动条可以访问最早和最新内容，保存日志也不依赖当前已显示的行。

自动滚动开启且没有选择时，新内容渲染后跟随末尾。关闭自动滚动或存在选择时，程序按文档字符位置保持当前浏览区域；追加、软折行和可见行回收不会改变已有选区。复制直接读取完整文档，所以 Tab、CR/LF 和跨屏内容不会因呈现方式丢失。

标题栏主菜单中的“终端字体设置…”支持 Cascadia Mono、Cascadia Code、Consolas、Courier New 和 Lucida Console，字号范围为 10–28 pt，默认为 Cascadia Mono 13 pt。修改字体会重新计算软折行，但不改变会话文本、选择位置或串口状态。

## 原始数据录制

连接后可选择 `.bin` 文件开始录制。录制从文件选择完成后的下一批新 RX 数据开始；再次点击、断开串口或关闭窗口时停止并刷新文件。

- 文件只包含录制期间设备返回的原始 RX 字节，不包含 TX、时间戳或方向。
- 已有终端历史不会写入；文本/HEX切换、编码、显示规范、清空和滚动都不会改变录制数据。
- 后台单写入者按接收顺序写盘，UI 变慢不会改变记录顺序。
- 停止时排空已经进入录制队列的数据，然后刷新并释放文件。
- 写盘失败或容量为 256 个缓冲块的后台队列耗尽时，录制会明确停止并提示，不会静默丢弃后继续显示为录制中。

原始录制与“保存日志”是两条独立路径：前者保存字节，后者保存当前文本或 HEX 模式下的格式化会话。

## 快捷指令

快捷指令面板默认关闭。每条指令包含名称、内容、文本/HEX模式和文本行尾，提供以下操作：

| 操作 | 行为 |
| --- | --- |
| 载入 | 复制到底部发送区，不立即发送 |
| 立即发送 | 直接发送，不改变底部发送区 |
| 删除 | 删除并立即保存 |

现有条目的名称和内容在失去焦点时保存；模式和行尾不能直接修改，需要删除后重新创建。最多保存 60 条，超过容量的本地配置或备份只加载前 60 条。

拖拽排序必须先进入“编辑排序”，并从专用手柄开始。多次拖拽只改变内存顺序，点击“完成”后才整体保存；保存失败时当前进程继续使用新顺序，可以再次尝试，重启后则恢复磁盘中最后成功保存的顺序。

列表循环发送会先验证全部条目，再按当前顺序创建快照。等待一个周期后发送第一条，以后每个周期发送下一条，末项之后重新从第一条开始，直到用户停止。运行期间禁止新增、编辑、删除、立即发送和排序，也不会自动滚动列表。

主菜单可以将完整列表导出为 UTF-8 JSON，或从不超过 10 MB 的 JSON 备份导入。导入先完成格式校验和覆盖确认，再整体替换并保存；取消、无效文件或保存失败都不会留下部分导入，保存失败时恢复原内存列表。

## 日志、计数与清空

- RX/TX 统计按实际成功接收或发送的字节数累计，与显示字符数无关。
- “保存日志”以 UTF-8 文本保存当前显示模式下自上次清空以来的完整格式化会话。
- “清空终端”同时清空文本和 HEX 会话、虚拟行索引、待渲染内容和计数，但不关闭串口或停止原始录制。
- 清空不会丢弃尚未交给 UI 的接收队列，也不会重置当前连接的流式解码状态；队列中的数据随后仍可能显示并重新累计。

## 设置与本地数据

标题栏主菜单包含“终端字体设置…”、“导入快捷指令…”、“导出快捷指令…”和“关于”。“关于”显示 Comet 版本、.NET 版本、运行时和操作系统信息。

用户数据位于：

```text
%LocalAppData%\Comet\settings.json
%LocalAppData%\Comet\presets.json
```

`settings.json` 保存终端字体和显示选项、最后使用的串口参数，以及底部发送模式、行尾和循环周期。活动连接、终端内容、RX/TX 计数和录制会话不会持久化。文件不存在、损坏或无法读取时使用内置默认值；保存时先写临时文件，再整体替换当前配置。

程序启动时只读取 `presets.json`，不会因初始化而创建、截断或规范化原文件。文件损坏或不可读时以空列表启动；明确执行新增、删除、编辑、完成排序或导入后，才用当前内存列表整体保存。

## 当前限制

- 终端显示接收队列没有固定容量；若设备输入长期快于 UI 处理速度，待处理数据会增加内存占用。
- 文本和 HEX 完整会话以及活动虚拟文档都位于内存，长时间高速接收会持续增加内存占用。
- 原始录制只保存 RX，不生成带时间戳的抓包容器，也不记录 TX。
- 内容区不提供本地回显，显示结果依赖设备返回。
- 已有快捷指令不能直接修改模式和行尾。
- 界面固定为浅色主题。
- 默认窗口和首选最小尺寸均为 1200 × 720。
- 真实串口、设备驱动、Windows UI 和大数据吞吐需要按测试指南进行设备或回环验证。
