# 虚拟化终端实现

Comet 的内容区使用自定义 `VirtualTerminalControl`，不再把完整接收会话交给 WinUI `TextBox`。本文件记录当前实现、行为不变量和后续维护边界；功能描述以源码和 [README](../README.md) 为准，验收方法见 [TESTING](TESTING.md)。

## 设计目标

- 内容区对用户表现为一个连续的纯文本交互表面。
- 完整会话长度与当前屏幕创建的 WinUI 元素数量分离。
- 多 MB 数据下保留最早内容、完整滚动范围和最新行跟随。
- 支持窗口宽度自动折行、跨行选择、复制、键入和粘贴发送。
- 保持文本/HEX、时间戳、RX/TX/SYS 前缀以及无本地回显等既有语义。

## 非目标

- 不实现本地回显；内容区只显示由设备回传的 RX 和按显示规则记录的条目。
- 不提供终端转义序列仿真、富文本编辑、语法高亮或协议专用 UI。
- 不在控件内部管理串口生命周期。
- 不把完整会话作为原始二进制抓包长期写盘。

## 组件关系

```text
SerialPortService
  -> 接收队列与 StreamingTextDecoder
  -> TerminalBuffer
       ├─ 文本格式化完整会话（分段）
       └─ HEX 格式化完整会话（分段）
  -> VirtualTerminalDocument（当前模式）
       ├─ 完整 UTF-16 文档
       └─ 固定单元格折行索引
  -> VirtualTerminalControl
       ├─ ScrollViewer + ItemsRepeater
       ├─ TerminalLinePresenter
       └─ 透明 TextBox 输入代理
```

`TerminalBuffer` 决定什么内容属于会话以及如何格式化。`VirtualTerminalDocument` 决定字符如何映射为显示行。`VirtualTerminalControl` 只管理可见元素、滚动和交互，不持有 `SerialPortService`。

## 完整会话存储

文本和 HEX 模式各自使用 `SegmentedTextStore` 保存不可变追加分段。常规接收只把新格式化结果挂到分段链表尾部，不拼接既有字符串。

- 切换“HEX 显示”时，从目标模式物化一次完整字符串并替换活动文档。
- 保存日志时，只物化当前模式的完整字符串。
- 清空终端同时清空两种模式的分段、活动文档和行索引。
- 当前没有基于字符数的历史淘汰；最早行和最新行都属于同一活动文档。

文本与 HEX 是格式化结果，不保留每一批原始 `byte[]`。因此 HEX 模式的字符量通常接近原始字节量的三倍。

## 行索引与增量更新

`VirtualTerminalDocument` 使用 `StringBuilder` 保存当前模式全文，使用 `TerminalDisplayLine` 列表保存折行结果。每行包含：

| 字段 | 含义 |
| --- | --- |
| `Start` | 行正文在完整文档中的 UTF-16 起点 |
| `Length` | 行正文长度，不含硬换行 |
| `BreakLength` | 行尾 CR、LF 或 CRLF 的长度；软折行为 0 |
| `Text` | 当前行用于呈现的文本，Tab 已按单元格展开为空格 |
| `CellCount` | 定宽字体下的显示单元格数量 |

普通追加只可能改变原来的最后一行并产生若干新行。实现步骤为：

1. 记住原末行的文档起点。
2. 把新字符追加到完整文档。
3. 从原末行起点重新计算后缀，不扫描更早的行。
4. 对原末行发送一个 `NotifyCollectionChangedAction.Replace`。
5. 通过 `ObservableCollection` 对新增行发送 `Add` 通知。

因此接收批次追加不会重置 `ItemsRepeater.ItemsSource`，也不会重建整份行列表。CR、LF、CRLF 形成硬换行；没有换行的数据按当前列数形成软折行。Tab 使用 4 列制表位；常见 CJK 和 emoji 按双单元格处理，组合字符不额外占单元格。

窗口宽度、字体或字号变化会改变列数。当前实现会同步重建完整折行索引，再通过文档字符锚点恢复视口；它不会改写 `TerminalBuffer` 中的两份完整会话。超长会话频繁调整窗口宽度仍可能产生一次明显的重排成本，这是后续可继续按区块惰性索引优化的部分。

## 可见行虚拟化

`VirtualTerminalControl` 内部使用 `ScrollViewer` 承载 `ItemsRepeater`，布局为零间距的垂直 `StackLayout`。`ItemsRepeater` 只创建视口附近的 `TerminalLinePresenter`，离开实现窗口的行元素会被回收；滚动条高度则由完整行集合决定。

每个呈现器只包含当前行的 `TextBlock` 和选区背景。行是内部渲染单元，不是用户可分别编辑的文本框；内容区对外仍是一个控件、一份文档和一组连续字符位置。

为了减少 UI 线程占用，页面先合并短时间内的接收字符，再把一个后缀交给控件。行集合的增量通知使 `ItemsRepeater` 保留既有虚拟化状态。

## 滚动规则

- 自动滚动开启且没有选择时，每次渲染后定位到完整文档末尾。
- 自动滚动关闭或存在选择时，追加前记录视口首行的文档字符起点和行内像素偏移，追加后恢复同一字符锚点。
- 调整窗口宽度后同样按字符锚点恢复，而不是使用可能已经失效的旧行号。
- 状态栏显示当前可见行范围、完整逻辑行数和活动会话字符数。

这些规则保证查阅历史时新数据不会把视口强制拉到底部，同时保证跟随模式持续显示最新行。

## 选择与复制

选区由 `_selectionAnchor` 和 `_selectionActive` 两个完整文档 UTF-16 偏移表示，不依赖可视元素是否已创建。

- 鼠标位置先映射到逻辑行，再按定宽单元格映射到文档字符偏移。
- 拖动到视口上下边缘时滚动并继续扩展选择。
- 每个可见行只绘制与全局选区的交集；跨行和硬换行属于同一选区。
- `Ctrl+A`、`Ctrl+C`、`Ctrl+Insert` 和右键菜单作用于完整文档。
- 复制直接从活动文档提取原始范围，因此不会复制 Tab 的显示填充空格，也不会丢失 CR/LF。
- 新数据追加不修改既有选区偏移；存在选区时暂停自动跟随。
- 输入代理获得焦点且没有选区时，当前行呈现器绘制闪烁的竖向虚拟光标；代理失焦或存在选区时隐藏。

方向键、Home、End、PageUp 和 PageDown 移动活动位置；按住 Shift 扩展选择。Delete 和 Backspace 不修改只读会话，也不发送数据。

## 键入与粘贴

控件内部保留一个 1×1、透明的 `TextBox` 作为 Windows 文本输入代理；显式把最小尺寸设为 0，避免默认文本框尺寸覆盖内容区命中范围。点击内容区后，焦点转移到代理：

1. `CharacterReceived` 获取当前键盘布局或输入法产生的组合字符，立即标记为已处理并通过 `InputReceived` 转发。
2. 剪贴板粘贴等不产生逐键字符的输入由 `TextChanged` 读取；使用重入保护立即清空代理。
3. 方向键、选择和复制快捷键先由终端交互层处理，不作为串口字符发送。
4. 页面应用当前字符编码和终端换行规则，再写入串口并增加 TX 字节计数。

这种方式保留键盘、输入法和粘贴入口，同时让显示文档只由接收/格式化链路修改。串口断开时只把输入代理设为只读；活动文档仍可滚动和复制。

## 复杂度与内存

| 操作 | 当前特征 |
| --- | --- |
| 普通追加 | 与原末行加新增后缀长度相关，不扫描历史行 |
| 屏幕渲染 | 与视口可见行及少量预取行相关 |
| 历史定位 | 行起点二分查找，复杂度为 `O(log n)` |
| 复制选区 | 与选区字符数相关 |
| 文本/HEX 切换 | 物化目标完整会话并重建全部行 |
| 窗口宽度变化 | 重建活动文档的全部折行索引 |
| 保存日志 | 物化当前模式完整会话并写入文件 |

当前文档位置使用 32 位 `int`，上限受 .NET 单个字符串和 `StringBuilder` 容量约束；实际可用规模还受内存限制。若未来需要持续运行到接近 2 GiB 字符，应先引入分块文档和 64 位逻辑位置，不能只修改字段类型。

## 维护不变量

修改内容区时必须保持以下条件：

1. `TerminalBuffer` 的旧分段不得在普通追加时拼接或删除。
2. `VirtualTerminalDocument.Append` 不得对历史全部行发送 `Reset`。
3. UI 行元素数量不得随完整会话行数线性增长。
4. 时间戳、方向和正文必须保持在同一纯文本文档中。
5. 文本/HEX 切换以完整会话为来源，不能从屏幕上的可见行反向转换。
6. 关闭自动滚动或存在选区时，新数据不得改变用户正在查阅的文档位置。
7. 键入和粘贴只发送，不直接修改活动文档。
8. 任意二进制输入在文本模式下允许显示替换字符或控制图形，但不得因无法解码而丢弃接收字节计数。
