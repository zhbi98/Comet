# 虚拟化终端实现

Comet 使用自定义 `VirtualTerminalControl` 显示终端会话，而不是把完整内容交给 WinUI `TextBox`。这样既能保留连续文本、选择和复制体验，也能让已创建的 UI 元素数量只与视口附近的行数有关。

本文说明终端内容区的数据模型、折行索引、虚拟化、滚动和输入实现。用户可见行为参见 [使用指南](USER_GUIDE.md)，接收线程与批处理链路参见 [软件架构](ARCHITECTURE.md)，验收方法参见 [测试指南](TESTING.md)。

## 设计边界

### 目标

- 内容区对用户表现为一个连续的纯文本交互表面。
- 完整会话长度与当前屏幕创建的 WinUI 元素数量分离。
- 多 MB 数据下保留最早内容、完整滚动范围和最新行跟随。
- 支持按窗口宽度软折行、跨行选择、复制、键入和粘贴发送。
- 保持文本/HEX、时间戳、RX/TX/SYS 前缀以及无本地回显等既有语义。

### 非目标

- 不实现本地回显；内容区只显示设备回传的 RX，以及按当前显示规则记录的条目。
- 不解析 ANSI/VT 转义序列，也不提供富文本编辑、语法高亮或协议专用 UI。
- 不在控件内部管理串口生命周期、字符解码或日志文件。
- 不把格式化会话当作原始二进制抓包长期写盘；原始录制由独立链路负责。

## 组件与职责

```text
SerialPortService
  -> ConnectionViewModel
  -> MainPage 接收队列与显示批处理
  -> TerminalViewModel
       ├─ StreamingTextDecoder
       └─ TerminalBuffer
            ├─ 文本格式化完整会话（分段存储）
            └─ HEX 格式化完整会话（分段存储）
  -> VirtualTerminalDocument（当前显示模式）
       ├─ 完整 UTF-16 活动文档
       └─ 固定单元格折行索引
  -> VirtualTerminalControl
       ├─ ScrollViewer + ItemsRepeater
       ├─ TerminalLinePresenter
       └─ 透明 TextBox 输入代理
```

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| `TerminalBuffer` | 决定哪些条目进入会话，生成并保存文本、HEX 两份格式化结果 | UI 折行、选择和滚动 |
| `VirtualTerminalDocument` | 保存当前模式全文，在 UTF-16 偏移、显示行和终端单元格之间映射 | 串口、剪贴板和 UI 元素 |
| `VirtualTerminalControl` | 虚拟化呈现、视口、选择、光标和输入转发 | 串口生命周期和会话格式化 |
| `TerminalLinePresenter` | 绘制一个可回收显示行 | 持有全局文档或交互状态 |

关键原则是：会话内容属于 `TerminalBuffer`，活动模式的行结构属于 `VirtualTerminalDocument`，可见元素属于 `VirtualTerminalControl`。三者不能相互替代。

## 会话格式化与存储

### 双模式完整会话

文本和 HEX 模式各自使用一个 `SegmentedTextStore`。它以不可变字符串为节点追加到链表尾部，普通接收不会重新拼接历史字符串。对于每个需要显示的条目，`TerminalBuffer` 在收到数据时同步生成两种格式，因此切换模式不依赖原始接收批次，也不从当前屏幕内容反向转换。

- 切换“HEX 显示”时，目标模式只物化一次完整字符串，再通过 `SetText` 替换活动文档。
- 保存日志时，只物化当前模式的完整会话并以 UTF-8 写入文件。
- 清空终端会清空两种分段会话、活动文档、行索引、待渲染后缀和收发计数。
- 清空属于显示操作，不重置流式解码器；跨接收批次的多字节字符状态仍属于当前连接。
- 当前没有基于字符数的历史淘汰，最早行与最新行都保留在同一会话中。

分段会话保存的是格式化文本，不长期持有每批 `byte[]`。HEX 字节使用空格分隔，因此不计前缀和换行时，`n` 个字节通常占 `3n - 1` 个字符。

### 格式边界

格式化状态跨越串口接收批次，因为一次回调不等于一个终端行。

- 连续 HEX 批次之间按需补一个空格，保证边界仍是 `AA BB`，不会粘成 `AABB`。
- 开启详细显示后，空闲间隔少于 200 ms、同方向且显示形式相同的 RX 批次延续为同一个流，不重复添加时间戳和方向前缀；间隔达到 200 ms 时开始新的详细条目。
- RX 空闲间隔使用单调时钟计算，与用于显示的本地时间分离；系统校时不会改变接收分组结果。
- 方向、详细模式或文本/HEX 表示发生变化时，按需先补行边界，再写入新条目。
- 未开启时间戳时，页面只把 RX 加入显示会话；内容区键入只发送，不生成本地 TX 回显。

### 文本规范化

RX 文本进入两份会话前已经由 `StreamingTextDecoder` 按当前编码流式解码。随后 `TerminalBuffer` 负责规范化显示字符：

| 输入 | 活动文本中的结果 |
| --- | --- |
| `CR`、`LF`、`CRLF` | 统一为一个 `CR` 硬换行 |
| 重复 `CR`，包括跨批次的 `CRCRLF` | 折叠为一个硬换行 |
| `CRLFCRLF` | 保留两个硬换行，表示真实空行 |
| Tab | 保留原始 `\t`，到显示行阶段再展开 |
| 其余 C0 控制字符 | 转换为 Unicode 控制图形 |
| DEL (`U+007F`) | 转换为 `U+2421` |
| 其他 Unicode 控制字符 | 转换为可见的 `\uXXXX` 文本 |

前一批是否以 `CR` 结束会保存在格式化状态中，所以被拆到不同接收回调的 `CRLF` 仍只产生一个换行。原始录制在这条格式化链路之前分支，记录内容不受上述规则影响。

`VirtualTerminalDocument` 仍能分别识别文档中的 `CR`、`LF` 和 `CRLF`，这是为了保持其文档模型独立；正常 RX 文本通常已经被规范为 `CR`。

## 活动文档与折行索引

`VirtualTerminalDocument` 使用 `StringBuilder` 保存当前显示模式的完整 UTF-16 文本，并使用 `ObservableCollection<TerminalDisplayLine>` 保存折行结果。每个显示行包含：

| 字段 | 含义 |
| --- | --- |
| `Start` | 行正文在活动文档中的 UTF-16 起点 |
| `Length` | 行正文的 UTF-16 长度，不含硬换行 |
| `BreakLength` | 行尾 `CR`、`LF` 或 `CRLF` 的长度；软折行为 `0` |
| `Text` | 提交给 `TextBlock` 的行文本；Tab 已展开为空格 |
| `CellCount` | 当前行占用的终端显示单元格数 |
| `End` | `Start + Length`，即正文末尾，不含硬换行 |

文档始终至少有一个显示行。空文档对应一个空行；若全文以硬换行结束，还会在末尾创建一个空行，使光标和滚动末端具有稳定位置。

### 状态转换

| 操作 | 文档与索引行为 | 视口行为 |
| --- | --- | --- |
| `Clear` | 清空全文并恢复单个空行 | 选区归零，立即滚动到顶部 |
| `Append` | 只重算原末行和新增后缀 | 跟随末尾，或恢复追加前的字符锚点 |
| `SetText` | 替换全文并重建全部显示行 | 跟随末尾，或按原滚动比例恢复 |
| `SetColumns` | 保留全文，重建全部显示行 | 按文档字符锚点恢复 |

文本/HEX 文档的字符位置没有一一对应关系，因此不跟随末尾的模式切换使用滚动比例，而不是沿用某个字符偏移；原选区端点会被截断到新文档长度。宽度或字体变化不替换文档，所以可以继续使用字符锚点并保留选区偏移。

### 增量追加

普通追加只可能改变原来的最后一个显示行，并在其后产生新行：新字符可能补全一个 `CRLF`、填满未完成行，或者触发新的软折行。实现按以下顺序更新：

1. 记录原末行的文档起点。
2. 把新字符追加到完整文档。
3. 从原末行起点重新计算后缀，不扫描更早的行。
4. 通过 `Replace` 通知替换原末行。
5. 通过 `Add` 通知追加其余新行。

追加期间不会重置 `ItemsRepeater.ItemsSource`。这使已经实现的视口窗口得以保留，也避免每个接收批次都回收全部可见元素。完整重建只发生在 `SetText` 或列数变化时。

### 单元格宽度与软折行

折行使用定宽终端单元格，而不是 UTF-16 代码单元数：

- Tab 使用 4 列制表位，其宽度取决于当前列；源文档仍保存一个 `\t`。
- `NonSpacingMark`、`EnclosingMark` 和 `Format` 类字符宽度为 0。
- 常见 Hangul、CJK、全角字符、emoji 和补充平面表意文字按 2 个单元格处理。
- 其他字符默认按 1 个单元格处理。
- UTF-16 代理项对作为一个 Unicode 码点处理；键盘左右移动不会把光标留在代理项中间。

若下一个字符会超过列宽，文档在该字符之前折行。为了保证索引始终前进，空行上的单个宽字符不会被拆分；在只有 1 列等极端宽度下，该行的 `CellCount` 可以暂时超过列数。

这是一套面向串口输出的宽度近似，不是完整的 Unicode 字素簇或文字塑形实现。组合序列、ZWJ emoji 和字体实际字形宽度可能与终端单元格模型不同；调整宽字符规则时，必须同时验证折行、点击定位、光标和选区。

## 布局与可见行虚拟化

`VirtualTerminalControl` 使用禁用水平滚动的 `ScrollViewer` 承载 `ItemsRepeater`，后者采用零间距垂直 `StackLayout`。完整行集合决定滚动范围，但 `ItemsRepeater` 只实现视口附近的 `TerminalLinePresenter`；离开实现窗口的元素可以回收复用。

字体或控件尺寸变化时，控件按以下方式计算布局：

1. 使用 100 个 `M` 测量当前字体，取平均值得到单元格宽度，降低单字测量的舍入误差。
2. 使用字体完整行框作为光标高度，显示行高度至少增加 1 DIP 的余量。
3. 从视口宽度中减去左右各 16 DIP，再除以单元格宽度并向下取整，得到至少为 1 的列数。
4. 列数变化时重建折行索引，并在布局完成后恢复字符锚点。

每个行呈现器由三层轻量元素组成，且自身不参与命中测试：

1. 选区矩形；
2. 不换行的 `TextBlock`；
3. 宽 1.5 DIP 的自定义光标矩形。

控件更新可见范围时，会把首尾各扩展 3 行作为预取范围，并只刷新已经实现的呈现器。全局选区、光标和文档位置始终保存在控件与文档中，不属于可回收行元素。

页面还会在调用 `AppendText` 前合并短时间内的格式化后缀，避免每个串口回调触发一次布局。具体的接收队列上限、时间片和渲染间隔由页面层负责，参见 [软件架构：接收](ARCHITECTURE.md#接收)。

## 滚动与视口恢复

- 自动滚动开启且没有选区时，追加后把选区活动位置移到文档末尾，并请求滚动到底部。
- 自动滚动关闭或存在选区时，追加前记录首个可见行的文档起点和行内像素偏移，布局后恢复同一锚点。
- 宽度、字体或字号引起重排时，同样使用字符锚点，不依赖已经失效的旧行号。
- 文本/HEX 完整替换且不跟随末尾时，按原来的滚动比例恢复，因为两份文档的字符偏移不同。
- 关闭自动滚动会取消尚未执行的“滚动到底部”请求。

`ItemsRepeater` 要到布局阶段才会更新 `ScrollableHeight`。因此滚动请求先以低优先级排入 UI 队列，并在 `UpdateLayout` 或 `LayoutUpdated` 后执行；如果过早调用，目标位置会被旧滚动范围截断。

文档偏移到显示行的定位使用行起点二分查找。位于软折行边界的偏移归到下一显示行，这让重排后的锚点和光标位置保持一致。状态栏中的行范围与总行数均指折行后的显示行，会话数字指当前模式的 UTF-16 字符数。

## 选择、复制与光标

选区由 `_selectionAnchor` 和 `_selectionActive` 两个活动文档 UTF-16 偏移表示，不依赖对应行是否已经创建。

- 鼠标位置先按行高映射到显示行，再扣除 16 DIP 左内边距并按单元格宽度映射到文档偏移。
- 点击宽字符时选择离指针最近的一侧，不会把位置落在 UTF-16 代理项对中间。
- 按住 Shift 点击或移动方向键时保留锚点并扩展选区。
- 拖动越过视口顶部或底部时，每次按 3 行高度滚动并继续更新活动端点。
- 每个已实现行只绘制全局选区与本行的交集；若选区只覆盖不可见的硬换行，呈现器补画一个单元格，使跨空行选择保持连续。
- `Ctrl+A`、`Ctrl+C`、`Ctrl+Insert` 和右键菜单作用于整份活动文档。
- 复制直接从源文档截取字符，因此保留 Tab 和 CR/LF，不会复制 Tab 的显示填充空格。

方向键按显示行和单元格导航；Home/End 移到当前显示行的正文边界，PageUp/PageDown 移动接近一页的显示行数。Delete 和 Backspace 始终被消费，既不修改只读会话，也不作为数据发送。

输入代理获得焦点且当前没有选区时，活动行呈现器绘制自定义竖向光标。光标约每 530 ms 切换可见状态；输入、点击或移动后立即重新显示，代理失焦或存在选区时隐藏。

## 键入与粘贴

控件保留一个 `1 × 1`、完全透明且 `MinWidth`/`MinHeight` 为 0 的原生 `TextBox` 作为 Windows 文本输入代理。点击内容区后，焦点转移到代理；显示文档本身仍保持只读。

`ScrollViewer` 和 `TextBox` 会先处理部分输入事件，因此控件使用 `handledEventsToo` 注册指针和按键处理器，确保选择、复制与导航仍能收到事件。

1. 普通键盘布局或输入法提交的文本通过 `TextChanged` 获取。
2. 控件先保存临时文本，再在重入保护下清空代理，最后通过 `InputReceived` 转发。
3. 粘贴使用专用 `Paste` 事件读取剪贴板文本，并把事件标记为已处理，避免随后再次进入普通键入路径。
4. 异步读取剪贴板期间若所有权变化或读取失败，异常被忽略，不中断终端会话。
5. 导航、选择、复制快捷键以及 Delete/Backspace 由交互层消费，不发送到串口。
6. 页面把输入交给 `PrepareTerminalInput`，应用当前字符编码和终端换行规则后写入串口，并按实际载荷增加 TX 字节计数。

普通键入不再同时订阅 `CharacterReceived`，因此每段已提交文本只有一条发送路径。串口断开时输入代理设为只读；已有文档仍可滚动、选择和复制。发送成功也不会直接修改活动文档，只有设备回传或其他显示条目才能改变它。

## 复杂度与内存

| 操作 | 当前特征 |
| --- | --- |
| 普通追加 | 与原末行加新增后缀长度相关，不扫描历史行 |
| 屏幕更新 | 与可见行及首尾各 3 行预取范围相关 |
| 文档偏移定位 | 对行起点执行二分查找，复杂度为 `O(log n)` |
| 复制选区 | 与选区字符数相关 |
| 文本/HEX 切换 | 物化目标完整会话并重建全部显示行 |
| 窗口或字体变化 | 重建活动文档的全部折行索引 |
| 保存日志 | 物化当前模式的完整会话并写入文件 |

当前文档位置、行起点和会话字符长度使用 32 位 `int`，上限受 .NET 单个字符串、`StringBuilder` 和可用内存约束。若未来需要接近 2 GiB 字符的持续会话，应同时引入分块活动文档与 64 位逻辑位置，不能只修改字段类型。

频繁调整超长会话的窗口宽度仍会产生同步全量重排成本；这是当前实现明确保留的优化空间，可考虑分块或惰性行索引。Unicode 单元格宽度也属于近似模型，不应把它描述为完整终端仿真。

## 维护不变量

修改终端内容区时必须保持以下条件：

1. `TerminalBuffer` 的历史分段不得在普通追加时被拼接或删除。
2. `VirtualTerminalDocument.Append` 不得重建全部历史行或发送集合 `Reset`。
3. UI 行元素数量不得随完整会话行数线性增长。
4. 时间戳、方向和正文必须保存在同一份连续纯文本文档中。
5. 文本/HEX 切换必须以各自的完整会话为来源，不能从可见行反向转换。
6. 关闭自动滚动或存在选区时，新数据不得改变用户正在查阅的文档位置。
7. 键入和粘贴只负责发送，不得直接修改活动文档。
8. 选区、光标和滚动锚点必须使用文档位置，不能依赖可回收的 UI 元素。
9. 任意二进制输入在文本模式下可以显示替换字符或控制图形，但接收字节计数不得因解码结果而丢失。

性能验收、选择边界和设备回环步骤维护在 [测试指南](TESTING.md)。实际测试结果应写入独立报告或 CI 工件，不写入 README 或本文。
