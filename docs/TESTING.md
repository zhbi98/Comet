## 测试现状

仓库当前没有独立的自动化测试项目。现阶段验证由以下部分组成：

1. .NET 还原与多架构编译。
2. 编码、HEX 和转义规则的针对性输入检查。
3. 实际设备或虚拟串口回环测试。
4. 大数据、随机二进制和断开竞态测试。
5. Windows 10/11 界面与便携包验证。

测试结果应保存在 CI 工件、发布记录或独立测试报告中，不写入 README。

## 提交前检查

### 基础检查

```powershell
dotnet restore .\Comet.csproj
dotnet build .\Comet.csproj -c Release -p:Platform=x64
git diff --check
```

涉及项目配置、依赖或本机代码时，额外验证目标架构：

```powershell
dotnet build .\Comet.csproj -c Release -p:Platform=x86
dotnet build .\Comet.csproj -c Release -p:Platform=ARM64
```

构建应无错误。警告需要确认来源；工程内损坏的 `obj` 或 NuGet 缓存应先清理并重新还原，不能把缓存警告当作源码结果。

### 变更影响范围

| 修改区域 | 最低附加验证 |
| --- | --- |
| `SerialPortService` | 枚举、连接、发送、接收、断开竞态 |
| `TerminalBuffer` | 文本/HEX 切换、100,000 字符淘汰、选择保持、大数据测试 |
| `StreamingTextDecoder` | UTF-8/GBK 跨批次字符、随机二进制、编码切换前重连 |
| `TextEscapeCodec` | 全部转义、非法 `\x`/`\u`、未知转义 |
| `HexCodec` | 分隔符、`0x`、奇数长度、非法字符 |
| `MainPage.xaml` | Windows 10/11、窗口最小尺寸、图标、滚动条、输入焦点 |
| 快捷指令 | 创建、载入、直接发送、编辑、删除、重启持久化 |
| 发布配置 | 干净机器启动、架构匹配、完整目录验证 |

## 测试环境

### 推荐连接方式

按优先级选择：

1. 一对物理串口交叉连接。
2. 能可靠回显和持续输出的开发板。
3. Windows 虚拟串口对。

仅使用单个会回显的设备时，应区分“应用发送成功”和“设备回传成功”，不能把本地输入误认为设备回显。

## 功能验收

### 端口与连接

| 编号 | 场景 | 操作 | 验收标准 |
| --- | --- | --- | --- |
| C01 | 初始枚举 | 启动应用 | 按 COM 数字排序，存在端口时默认选中第一项 |
| C02 | 设备说明 | 连接带友好名称的 USB 串口 | 保留 `CH340`、`CP210x` 等名称；不显示 `VID_xxxx`、`PID_xxxx` |
| C03 | 名称回退 | 使用无法读取友好名称的端口 | 仅显示 `COMx`，仍可连接 |
| C04 | 刷新保留 | 选择端口后刷新 | 端口仍存在时保持选择，不存在时选择第一项或为空 |
| C05 | 参数映射 | 逐项改变串口参数后连接 | 波特率、数据位、停止位、校验、流控制、DTR、RTS 与 UI 一致 |
| C06 | 连接状态 | 连接和断开 | 参数区锁定/解锁；底部状态、按钮文字和窗口标题同步变化 |
| C07 | 重复连接 | 连续执行连接、断开至少 20 次 | 无端口占用残留、未处理异常或 UI 失去响应 |
| C08 | 端口占用 | 用其他程序占用端口后连接 | 显示连接失败信息，应用保持可用 |

### 底部文本发送

| 编号 | 输入或场景 | 验收标准 |
| --- | --- | --- |
| S01 | `help`，行尾“无” | 发送所选编码的 4 个字符，不追加换行 |
| S02 | `help`，分别选择 CR、LF、CRLF | 依次追加 `0D`、`0A`、`0D 0A` |
| S03 | `help\r\n` | 转义为正文中的 CRLF；再按行尾设置决定是否额外追加 |
| S04 | `\0\a\b\f\n\r\t\v` | 发送对应控制字符 |
| S05 | `\x41\u4F60` | 解码为 `A你`，再按所选字符编码生成字节 |
| S06 | `\x0`、`\xGG`、`\u123` | 拒绝发送并显示转义格式错误 |
| S07 | `\q` | 保留为两个字符 `\q` |
| S08 | 空文本、行尾“无” | 拒绝发送并提示没有内容 |
| S09 | 空文本、行尾 CR | 只发送 `0D` |
| S10 | UTF-8、GBK、ASCII | 对可表示文本发送对应编码；ASCII 不可表示字符按 .NET ASCII 回退规则处理 |

TX 计数按最终成功写入串口的字节数增加。时间戳开启时，底部文本发送会生成 TX 显示条目。

### HEX 发送

| 编号 | 输入 | 验收标准 |
| --- | --- | --- |
| H01 | `31 32 33` | 发送 3 字节 `31 32 33` |
| H02 | `0x31,0x32:0x33` | 忽略前缀和分隔符，发送相同 3 字节 |
| H03 | `AA-BB_CC;DD` | 连字符、下划线、分号被忽略 |
| H04 | `1 23` | 去除分隔符后长度为奇数，拒绝发送 |
| H05 | `GG` 或空内容 | 拒绝发送并显示 HEX 格式错误 |
| H06 | HEX 模式选择 CRLF | 不自动追加行尾；需要显式加入 `0D 0A` |

### 内容区键入同步发送

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| K01 | 未连接时点击、选择和复制内容 | 可以选择复制，不能修改或发送 |
| K02 | 连接后逐字输入 `help` | 每次新增字符立即发送；字符不会直接留在内容区 |
| K03 | 粘贴多字符文本 | 新增文本一次发送，不重复发送已有内容 |
| K04 | 输入字面量 `\r`、`\n` | 发送反斜杠和字母，不做转义解释 |
| K05 | 行尾“无”时按 Enter | 发送 LF (`0A`) |
| K06 | 行尾为 CR、LF、CRLF 时按 Enter | 发送所选行尾 |
| K07 | 粘贴含 CR、LF、CRLF 的多行文本 | 所有真实换行统一转换为当前行尾；“无”时转换为 LF |
| K08 | 删除、移动光标、选择、复制 | 不发送数据，显示内容不被用户编辑改变 |
| K09 | 设备不回显 | 输入后内容区不出现本地输入，TX 计数正常增加 |
| K10 | 设备回显 | 只显示设备返回的数据，RX 与 TX 分别按字节累计 |

内容区输入不会生成本地 TX 文本条目，即使时间戳已开启。

### 循环发送

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| R01 | 周期 1000 ms | 开启后等待约一个周期再首次发送，之后重复发送当前底部内容 |
| R02 | 周期小于 20 或大于 60,000 | 实际计时限制在 20–60,000 ms |
| R03 | 未连接时开启 | 开关自动恢复关闭并提示先连接 |
| R04 | 内容无效或发送失败 | 循环自动停止并提示检查连接或内容 |
| R05 | 主动断开 | 循环停止，开关恢复关闭 |

### 接收与显示

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| D01 | UTF-8 多字节字符拆成多个接收批次 | 字符完整显示，不因批次边界产生额外 `?` |
| D02 | GBK 中文和 ASCII 文本 | 按连接前选择的编码显示 |
| D03 | 无效字节序列 | 文本模式显示 `?`，应用不退出 |
| D04 | CR、LF、CRLF | 显示为正常换行，不按接收批次增加空白行 |
| D05 | NUL 和其他 C0 控制字符 | CR/LF 换行、Tab 保留，其余显示控制图形；不截断后续内容 |
| D06 | 无换行长文本 | 按内容区宽度自动折行，窗口调整后重新排版 |
| D07 | HEX 显示 | 每字节两位大写字符，字节间一个空格 |
| D08 | 切换文本/HEX | 当前视图立即切换，继续接收时使用新显示模式 |
| D09 | 时间戳默认状态 | 启动时开启，显示毫秒时间和 RX/TX/SYS 前缀 |
| D10 | 关闭时间戳 | 之后只显示 RX；TX 和 SYS 不写入显示缓冲 |
| D11 | 再次开启时间戳 | 已有内容不重写，之后的新条目恢复详细前缀 |
| D12 | 连续 RX 批次 | 数据连续拼接，不为每个底层接收事件重复插入时间戳或换行 |
| D13 | TX/RX 交替 | 不同方向之间保持清晰行边界 |

### 选择、滚动与缓冲

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| B01 | 自动滚动开启，无选择 | 每次渲染后显示最新内容 |
| B02 | 自动滚动关闭 | 新数据不强制跳到底部 |
| B03 | 选择一行或多行 | 新数据追加时不崩溃，选择范围尽量保持 |
| B04 | 复制时间戳、方向和正文 | 作为同一段纯文本复制 |
| B05 | 文本超过 100,000 字符 | 只淘汰最早前缀，当前视图保持最新约 100,000 字符 |
| B06 | HEX 超过 100,000 字符 | 头部从完整字节标记开始，不保留半个 HEX 字节 |
| B07 | 文本淘汰 Unicode 代理对边界 | 当前文本不以低代理字符开头 |
| B08 | 满缓冲时切换文本/HEX | 两个视图分别显示各自最近 100,000 字符，不要求时间范围完全一致 |
| B09 | 满缓冲时保留选择 | 头部淘汰后选择索引安全修正，无越界或崩溃 |

### 快捷指令与持久化

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| P01 | 首次启动且无 `presets.json` | 以空列表启动，并在初始化保存时创建文件 |
| P02 | 添加文本预设 | 保存名称、内容、行尾和文本模式 |
| P03 | 添加 HEX 预设 | 保存 HEX 模式；发送时不自动追加行尾 |
| P04 | 点击“载入” | 将内容、HEX 状态、行尾复制到底部发送区，不发送 |
| P05 | 点击立即发送图标 | 直接发送预设，不改变底部发送区 |
| P06 | 编辑名称或内容 | 失去焦点时保存；空名称改为“未命名指令” |
| P07 | 修改已有模式或行尾 | 当前 UI 不支持直接修改，应删除并重新创建 |
| P08 | 删除预设 | UI 和 JSON 同时删除对应条目 |
| P09 | 重启应用 | 恢复上次保存的有效预设 |
| P10 | JSON 无效或无法读取 | 按空列表启动；确认初始化可能用空列表覆盖原文件 |

### 日志、计数和清空

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| L01 | 保存文本视图 | 以 UTF-8 `.txt` 保存当前文本缓冲 |
| L02 | 保存 HEX 视图 | 保存当前 HEX 缓冲，而不是隐藏的文本视图 |
| L03 | 缓冲已淘汰旧内容 | 日志只包含当前最多 100,000 个字符，不承诺完整会话 |
| L04 | 空内容保存 | 不打开有效保存流程，提示当前日志为空 |
| L05 | 取消文件选择 | 不写文件，不显示错误 |
| L06 | 清空终端 | 两个显示缓冲、待渲染内容和 RX/TX 计数清零，串口保持连接 |
| L07 | RX/TX 计数 | 按字节累计；显示字符、HEX 空格和时间戳不计入 |
| L08 | 接收积压时清空 | 已进入接收队列但尚未处理的数据允许在清空后继续显示并重新累计 RX |

## 大数据与二进制测试

### 数据组成

测试数据应混合：

- 连续可打印 ASCII
- UTF-8 或 GBK 多字节文本
- CR、LF、CRLF 和长无换行段
- NUL、Tab、DEL 和其他控制字节
- 随机 `00`–`FF` 二进制数据

### 操作步骤

1. 连接稳定回显设备或虚拟串口对。
2. 先以文本模式持续接收，累计 RX 至少 2–3 MB。
3. 在接收过程中切换 HEX 显示、时间戳和自动滚动。
4. 反复选择并复制多行内容，移动滚动条并调整窗口尺寸。
5. 操作底部发送框、快捷指令输入框和端口区域，确认焦点仍可响应。
6. 继续运行至少 10 分钟，期间多次达到 100,000 字符上限。
7. 清空内容后继续接收，确认计数从零重新累计且连接未断开。

### 验收标准

- 应用持续响应，不因大字符串重建而长时间卡死。
- RX 计数持续增长，显示缓冲只淘汰最早内容。
- 最新数据可在自动滚动开启时看到。
- 文本与 HEX 切换后格式正确，不出现半个 HEX 字节。
- 随机二进制不会截断其后的数据或导致应用退出。
- 所有输入框、按钮、复选框和滚动条仍可交互。
- 多行选择和复制期间没有越界、未授权访问或应用崩溃。

显示缓冲最多保留 100,000 个字符，因此不能用内容区长度判断完整会话是否丢字节；应结合 RX 字节计数和发送端统计判断。

## 断开与关闭竞态测试

1. 让设备持续发送数据，使 UI 保持有待渲染增量。
2. 在文本选择存在、自动滚动开启和关闭三种状态下分别断开。
3. 在大流量期间直接关闭窗口。
4. 重启应用并重新打开同一端口。
5. 重复上述过程至少 20 次。

验收标准：

- 不出现未处理的 `UnauthorizedAccessException`。
- 已排队的 UI 更新不会在页面卸载后访问无效控件。
- 串口可再次被 Comet 或其他工具正常打开。
- 循环发送计时器和终端渲染计时器停止。
- 关闭过程中允许收到错误提示，但应用不能异常退出或长期无响应。

## 发布验证

便携包应在未安装开发环境的目标设备上验证：

| 项目 | 验收标准 |
| --- | --- |
| 目录完整性 | 从完整解压目录启动，不能只测试单独 EXE |
| 系统 | 至少覆盖 Windows 10 1809+ 和 Windows 11 |
| 架构 | 发布包与 x86、x64 或 ARM64 目标一致 |
| 视觉 | 标题栏、应用图标、任务栏图标、按钮符号和文字正常 |
| 布局 | 1280 × 820、最小 1200 × 720 和系统缩放下无遮挡 |
| 快捷面板 | 默认关闭，打开后列表与滚动条不遮挡卡片 |
| 串口 | 能枚举、连接、收发和断开实际 USB 串口 |
| 持久化 | 重启后快捷指令恢复，日志可保存到用户选择位置 |
| 运行时 | 不要求用户另外安装 .NET 或 Windows App SDK Runtime |
