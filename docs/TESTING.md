## 测试现状

仓库包含 `tests/Comet.Tests` 自动化测试项目。当前验证由以下部分组成：

1. .NET 还原与多架构编译。
2. 核心发送、双视图会话、流式解码和循环发送 ViewModel 的自动化回归测试。
3. 实际设备或虚拟串口回环测试。
4. 大数据、随机二进制和断开竞态测试。
5. Windows 10/11 界面与便携包验证。

测试结果应保存在 CI 工件、发布记录或独立测试报告中，不写入 README。

## 提交前检查

### 基础检查

```powershell
dotnet restore .\Comet.sln
dotnet build .\Comet.sln -c Release -p:Platform=x64
dotnet test .\tests\Comet.Tests\Comet.Tests.csproj -c Release
git diff --check
```

涉及项目配置、依赖或本机代码时，额外验证目标架构：

```powershell
dotnet build .\src\Comet\Comet.csproj -c Release -p:Platform=x86
dotnet build .\src\Comet\Comet.csproj -c Release -p:Platform=ARM64
```

构建应无错误。警告需要确认来源；工程内损坏的 `obj` 或 NuGet 缓存应先清理并重新还原，不能把缓存警告当作源码结果。

## 测试环境

### 推荐连接方式

按优先级选择：

1. 一对物理串口交叉连接。
2. 能可靠回显和持续输出的开发板。
3. Windows 虚拟串口对。

仅使用单个会回显的设备时，应区分“应用发送成功”和“设备回传成功”，不能把本地输入误认为设备回显。

## 功能验收

### 端口与连接

| 编号 | 场景 | 操作 | 验收标准 |
| --- | --- | --- | --- |
| C01 | 初始枚举 | 启动应用 | 按 COM 数字排序，存在端口时默认选中第一项 |
| C02 | 设备说明 | 连接带友好名称的 USB 串口 | 保留 `CH340`、`CP210x` 等名称；不显示 `VID_xxxx`、`PID_xxxx` |
| C03 | 名称回退 | 使用无法读取友好名称的端口 | 仅显示 `COMx`，仍可连接 |
| C04 | 刷新保留 | 选择端口后刷新 | 端口仍存在时保持选择，不存在时选择第一项或为空 |
| C05 | 参数映射 | 逐项改变串口参数后连接 | 波特率、数据位、停止位、校验、流控制、DTR、RTS 与 UI 一致 |
| C06 | 连接状态 | 连接和断开 | 参数区锁定/解锁；底部状态、按钮文字和窗口标题同步变化 |
| C07 | 重复连接 | 连续执行连接、断开至少 20 次 | 无端口占用残留、未处理异常或 UI 失去响应 |
| C08 | 端口占用 | 用其他程序占用端口后连接 | 显示连接失败信息，应用保持可用 |
| C09 | 物理拔插 | 通信中拔出 USB 串口，再插回同一设备 | UI 保持原连接状态且不增加 SYS 文本；同一 COM 口恢复后自动重连并继续收发，无需点击连接 |
| C10 | 取消恢复 | 设备拔出后点击“断开串口” | 返回未连接、参数区解锁；之后插回设备不会被应用自动占用 |

### 底部文本发送

| 编号 | 输入或场景 | 验收标准 |
| --- | --- | --- |
| S01 | `help`，行尾“无” | 发送所选编码的 4 个字符，不追加换行 |
| S02 | `help`，分别选择 CR、LF、CRLF | 依次追加 `0D`、`0A`、`0D 0A` |
| S03 | `help\r\n` | 转义为正文中的 CRLF；再按行尾设置决定是否额外追加 |
| S04 | `\0\a\b\f\n\r\t\v` | 发送对应控制字符 |
| S05 | `\x41\u4F60` | 解码为 `A你`，再按所选字符编码生成字节 |
| S06 | `\x0`、`\xGG`、`\u123` | 拒绝发送并显示转义格式错误 |
| S07 | `\q` | 保留为两个字符 `\q` |
| S08 | 空文本、行尾“无” | 拒绝发送并提示没有内容 |
| S09 | 空文本、行尾 CR | 只发送 `0D` |
| S10 | UTF-8、GBK、ASCII | 对可表示文本发送对应编码；ASCII 不可表示字符按 .NET ASCII 回退规则处理 |

TX 计数按最终成功写入串口的字节数增加。时间戳开启时，底部文本发送会生成 TX 显示条目。

### HEX 发送

| 编号 | 输入 | 验收标准 |
| --- | --- | --- |
| H01 | `31 32 33` | 发送 3 字节 `31 32 33` |
| H02 | `0x31,0x32:0x33` | 忽略前缀和分隔符，发送相同 3 字节 |
| H03 | `AA-BB_CC;DD` | 连字符、下划线、分号被忽略 |
| H04 | `1 23` | 去除分隔符后长度为奇数，拒绝发送 |
| H05 | `GG` 或空内容 | 拒绝发送并显示 HEX 格式错误 |
| H06 | HEX 模式选择 CRLF | 不自动追加行尾；需要显式加入 `0D 0A` |

### 内容区键入同步发送

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| K01 | 未连接时点击、选择和复制内容 | 可以选择复制，不能修改或发送 |
| K02 | 连接后逐字输入 `help` | 每次新增字符立即发送；字符不会直接留在内容区 |
| K03 | 粘贴多字符文本 | 新增文本一次发送，不重复发送已有内容 |
| K04 | 输入字面量 `\r`、`\n` | 发送反斜杠和字母，不做转义解释 |
| K05 | 行尾“无”时按 Enter | 发送 LF (`0A`) |
| K06 | 行尾为 CR、LF、CRLF 时按 Enter | 发送所选行尾 |
| K07 | 粘贴含 CR、LF、CRLF 的多行文本 | 所有真实换行统一转换为当前行尾；“无”时转换为 LF |
| K08 | 删除、移动光标、选择、复制 | 不发送数据，显示内容不被用户编辑改变 |
| K09 | 设备不回显 | 输入后内容区不出现本地输入，TX 计数正常增加 |
| K10 | 设备回显 | 只显示设备返回的数据，RX 与 TX 分别按字节累计 |
| K11 | 点击内容区、失焦、重新聚焦和建立选区 | 无选区且聚焦时显示闪烁竖向光标；失焦或选择文本时隐藏 |

内容区输入不会生成本地 TX 文本条目，即使时间戳已开启。

### 循环发送

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| R01 | 周期 1000 ms | 开启后等待约一个周期再首次发送，之后重复发送当前底部内容 |
| R02 | 周期小于 20 或大于 60,000 | 实际计时限制在 20–60,000 ms |
| R03 | 未连接时开启 | 开关自动恢复关闭并提示先连接 |
| R04 | 内容无效或发送失败 | 循环自动停止并提示检查连接或内容 |
| R05 | 主动断开 | 循环停止，开关恢复关闭 |
| R06 | 周期 100 ms，记录至少 30 个连续 TX 时间戳 | 相邻 TX 平均周期为 98–102 ms；UI 刷新或 RX 应答不造成持续累积漂移 |
| R07 | 快捷指令循环发送期间开启底部循环发送 | 快捷指令列表循环停止，只保留底部循环；反向操作时同样只保留快捷指令循环 |

循环发送采用 Windows 高分辨率等待计时器，但 Windows 不是硬实时系统。验收以连续样本的平均周期和是否存在累积漂移为准，不要求每一个单次间隔绝对等于设定值。

### 接收与显示

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| D01 | UTF-8 多字节字符拆成多个接收批次 | 字符完整显示，不因批次边界产生额外 `?` |
| D02 | GBK 中文和 ASCII 文本 | 按连接前选择的编码显示 |
| D03 | 无效字节序列 | 文本模式显示 `?`，应用不退出 |
| D04 | CR、LF、CRLF、CRCRLF、CRLFCRLF | `CRLF`、`LF`、`CR` 各显示一个换行；`CRCRLF` 兼容为一个换行；`CRLFCRLF` 保留两个换行表示真正空行 |
| D05 | NUL 和其他 C0 控制字符 | CR/LF 换行、Tab 保留，其余显示控制图形；不截断后续内容 |
| D06 | 无换行长文本 | 按内容区宽度自动折行，窗口调整后重新排版 |
| D07 | HEX 显示 | 每字节两位大写字符，字节间一个空格 |
| D08 | 切换文本/HEX | 当前视图立即切换，继续接收时使用新显示模式 |
| D09 | 时间戳默认状态 | 启动时开启，显示毫秒时间和 RX/TX/SYS 前缀 |
| D10 | 关闭时间戳 | 之后只显示 RX；TX 和 SYS 不写入显示缓冲 |
| D11 | 再次开启时间戳 | 已有内容不重写，之后的新条目恢复详细前缀 |
| D12 | 相邻 RX 批次间隔少于 200 ms | 数据连续拼接，不为每个底层接收事件重复插入时间戳或换行 |
| D13 | 相邻 RX 批次间隔达到 200 ms | 新数据另起详细条目，显示新的接收时间戳和 RX 前缀 |
| D14 | TX/RX 交替 | 不同方向之间保持清晰行边界 |

### 用户设置持久化

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| U01 | 首次启动且无 `settings.json` | 使用内置默认字体、终端显示、串口和发送选项正常启动，不要求预先创建配置文件 |
| U02 | 修改终端、串口和发送选项后重启 | 恢复字体与显示选项、最后选择的可用端口、串口参数、发送模式、行尾和循环周期 |
| U03 | 保存设置后重启 | 不恢复活动连接、终端会话、RX/TX 计数或原始录制会话 |
| U04 | `settings.json` 损坏、无法读取或缺少设置分组 | 应用不退出；损坏或不可读文件使用完整默认值，缺少的分组使用对应默认值 |
| U05 | 设置保存期间发生写入或替换失败 | 当前进程中的界面状态仍可使用，原有有效配置不会被半写入内容替代 |

### 快捷指令与持久化

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| P01 | 首次启动且无 `presets.json` | 以空列表启动，不在初始化阶段创建文件；首次保存动作发生后再创建 |
| P02 | 添加文本预设 | 保存名称、内容、行尾和文本模式 |
| P03 | 添加 HEX 预设 | 保存 HEX 模式；发送时不自动追加行尾 |
| P04 | 点击“载入” | 将内容、HEX 状态、行尾复制到底部发送区，不发送 |
| P05 | 点击立即发送图标 | 直接发送预设，不改变底部发送区 |
| P06 | 编辑名称或内容 | 失去焦点时保存；空名称改为“未命名指令” |
| P07 | 修改已有模式或行尾 | 当前 UI 不支持直接修改，应删除并重新创建 |
| P08 | 删除预设 | UI 和 JSON 同时删除对应条目 |
| P09 | 重启应用 | 恢复上次保存的有效预设 |
| P10 | JSON 无效或无法读取 | 按空列表启动，初始化不覆盖原文件，便于手动恢复和排查 |
| P11 | 导出 JSON | 生成 UTF-8 `.json` 文件，包含当前全部名称、内容、模式、行尾和 ID |
| P12 | 导入有效 JSON 后取消确认 | 当前列表和本地 `presets.json` 均不改变 |
| P13 | 导入有效 JSON 并确认 | 当前列表整体替换、计数同步更新，并立即写入本地存储 |
| P14 | 导入无效 JSON、缺少 Command 或超过 10 MB | 显示失败原因，当前列表不改变 |
| P15 | 导入包含重复或空 ID、未知行尾 | 为冲突 ID 生成新值，未知行尾规范为“无” |
| P16 | 导入后保存失败 | 内存列表回滚到导入前状态，不保留部分导入结果 |
| P17 | 默认状态拖动手柄或卡片 | 不启动拖拽，列表顺序不变 |
| P18 | 点击“编辑排序”并拖动手柄 | 使用 ListView 内置动画重排，输入框和按钮区域不能启动拖拽 |
| P19 | 连续调整多条指令但未点击“完成” | 只改变内存顺序，不写入 `presets.json` |
| P20 | 点击“完成” | 退出排序模式，只写入一次最终顺序，重新启动后保持该顺序 |
| P21 | 拖拽到视口上下边缘 | 列表正常滚动，可把项目移动到当前视口外的位置 |
| P22 | 只有零条或一条指令 | “编辑排序”不可用，不影响添加、编辑和发送功能 |
| P23 | 点击“完成”时保存失败 | 显示保存错误，当前进程继续保留新顺序，磁盘文件保持最后一次成功保存的顺序 |
| P24 | 保存失败后关闭应用并重新启动 | 丢弃未保存的内存顺序，重新载入磁盘中的旧顺序 |
| P25 | 手动添加至 60 条 | 第 60 条正常保存，随后“添加”按钮不可用，列表不能继续增加 |
| P26 | 本地配置或导入备份超过 60 条 | 仅按文件顺序加载前 60 条；启动读取不改写本地文件，后续保存动作才用当前 60 条重写 |
| P27 | 列表为空 | “循环发送”不可用；添加第 1 条后自动可用 |
| P28 | 3 条文本/HEX混合指令 | 按列表顺序逐条发送，每条分别使用卡片的文本/HEX和行尾定义 |
| P29 | 周期设置为 100 ms 后启动循环发送 | 等待约 100 ms 发送第 1 条，之后每约 100 ms 发送下一条 |
| P30 | N 条指令完成一轮 | 第 N 条之后继续发送第 1 条，开关保持开启，直到点击“停止发送” |
| P31 | 列表循环发送进行中 | 列表不自动滚动，新增区、卡片操作和排序暂时不可用；停止后恢复 |
| P32 | 序列中存在无效 HEX、转义或空内容 | 启动前整体拒绝，不发送任何一条，并指出需要检查的卡片 |
| P33 | 列表循环发送期间断开串口、导入列表或发生写入失败 | 当前循环停止，开关恢复关闭，不再发送剩余条目 |

### 日志、计数和清空

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| L01 | 保存文本视图 | 以 UTF-8 `.txt` 保存自上次清空以来的完整格式化文本会话 |
| L02 | 保存 HEX 视图 | 保存完整 HEX 会话，而不是隐藏的文本视图或仅当前可见窗口 |
| L03 | 大会话中只渲染少量可见行 | 日志仍包含完整活动模式内容，不依赖已创建的行元素 |
| L04 | 空内容保存 | 不打开有效保存流程，提示当前日志为空 |
| L05 | 取消文件选择 | 不写文件，不显示错误 |
| L06 | 清空终端 | 两个显示缓冲、待渲染内容和 RX/TX 计数清零，串口保持连接 |
| L07 | RX/TX 计数 | 按字节累计；显示字符、HEX 空格和时间戳不计入 |
| L08 | 接收积压时清空 | 已进入接收队列但尚未处理的数据允许在清空后继续显示并重新累计 RX |

### 原始数据录制

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| REC01 | 未连接时点击“开始录制” | 不创建录制会话，提示先连接串口 |
| REC02 | 终端已有历史后开始录制 | `.bin` 不包含开始前已经显示的内容 |
| REC03 | 录制随机 `00`–`FF` 字节 | 文件与设备在开始/停止边界内发送的原始字节逐字节一致 |
| REC04 | 录制时切换文本/HEX、编码、时间戳和滚动 | 文件内容不发生转换，不插入显示前缀或换行 |
| REC05 | 清空终端后继续录制 | 文件继续追加，清空只影响显示会话 |
| REC06 | 点击停止后设备继续发送 | 停止前已入队数据完成刷新，停止后的新 RX 不再进入文件 |
| REC07 | 录制时断开或关闭窗口 | 文件安全关闭，可立即读取、移动或删除，串口正常释放 |
| REC08 | 写盘失败或后台队列耗尽 | 录制明确停止并提示错误，不静默丢数据后继续显示录制中 |

## 大数据与二进制测试

### 数据组成

测试数据应混合：

- 连续可打印 ASCII
- UTF-8 或 GBK 多字节文本
- CR、LF、CRLF 和长无换行段
- NUL、Tab、DEL 和其他控制字节
- 随机 `00`–`FF` 二进制数据

### 操作步骤

1. 连接稳定回显设备或虚拟串口对。
2. 先以文本模式持续接收，累计 RX 至少 2–3 MB。
3. 在接收过程中切换 HEX 显示、时间戳和自动滚动。
4. 反复选择并复制多行内容，移动滚动条并调整窗口尺寸。
5. 操作底部发送框、快捷指令输入框和端口区域，确认焦点仍可响应。
6. 继续运行至少 10 分钟，期间多次滚动到最早、中间和最新位置。
7. 接收中开始原始录制，至少写入 2–3 MB；切换显示并清空内容后继续录制，再手动停止。
8. 对比 `.bin` 的长度和哈希或逐字节内容，确认只包含录制时间范围内的 RX 数据。
9. 清空内容后继续接收，确认计数从零重新累计且连接未断开。

### 验收标准

- 应用持续响应，不因大字符串重建而长时间卡死。
- RX 计数、完整会话长度和逻辑行数持续增长，最早内容不因 UI 视口容量消失。
- 最新数据可在自动滚动开启时看到。
- 文本与 HEX 切换后格式正确，不出现半个 HEX 字节。
- 随机二进制不会截断其后的数据或导致应用退出。
- 所有输入框、按钮、复选框和滚动条仍可交互。
- 多行选择和复制期间没有越界、未授权访问或应用崩溃。

应结合状态栏会话长度、最早/最新行定位、保存日志、原始 `.bin`、RX 字节计数和发送端统计验证数据完整性。`ItemsRepeater` 只创建少量行元素是正常的，不能用 UI 自动化树中的元素数量推断完整会话行数；日志是格式化会话，原始录制文件才用于逐字节验证 RX。

## 断开与关闭竞态测试

1. 让设备持续发送数据，使 UI 保持有待渲染增量。
2. 在文本选择存在、自动滚动开启和关闭三种状态下分别断开。
3. 在大流量期间直接关闭窗口。
4. 通信期间拔出 USB 串口，确认 UI 不显示额外状态或 SYS 文本，再插回并验证自动恢复双向通信。
5. 再次拔出后点击“断开串口”，插回设备并确认 Comet 不会自动占用端口。
6. 重启应用并重新打开同一端口。
7. 重复上述过程至少 20 次。

验收标准：

- 不出现未处理的 `UnauthorizedAccessException`。
- 已排队的 UI 更新不会在页面卸载后访问无效控件。
- 串口可再次被 Comet 或其他工具正常打开。
- 自动重连只能接管原 COM 口；手动取消、正常断开和窗口关闭后不得继续尝试打开端口。
- 定时发送计时器和终端渲染计时器停止。
- 原始录制队列完成排空，文件已刷新并释放。
- 窗口 `Closed` 与页面 `Unloaded` 即使先后触发，也只执行一次串口关闭流程。
- 关闭过程中允许收到错误提示，但应用不能异常退出或长期无响应。
