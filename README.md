# Comet

  <img src="Assets/CometTerminalIcon.png" alt="Comet 应用图标" width="96" />

<p align="center">面向嵌入式开发的通用 Windows 串口调试终端</p>

Comet 使用 C#、WinUI 3 和 Windows App SDK 开发，提供串口配置、文本/HEX 收发、终端键入、循环发送和快捷指令等常用能力。它不绑定特定开发板、仪表或私有协议，可用于 MCU、Linux 开发板、模组和其他串口设备。

项目采用 `Unpackaged + self-contained` 模式：开发调试不需要注册 MSIX，发布版本解压后即可运行。

## 功能概览

| 分类 | 支持内容 |
| --- | --- |
| 串口连接 | 自动扫描 COM 端口；波特率、数据位、停止位、校验位、流控制、DTR 和 RTS |
| 字符编码 | UTF-8、GBK、ASCII |
| 数据收发 | 文本发送、HEX 发送、HEX 显示、CRLF/CR/LF 行尾、文本转义 |
| 终端交互 | 内容区键入与粘贴后立即发送、设备回传显示、多行选择和复制、自动滚动 |
| 数据记录 | 毫秒级时间戳、RX/TX/SYS 标识、RX/TX 字节统计、UTF-8 日志保存 |
| 自动化 | 20～60,000 ms 循环发送、可持久化的通用快捷指令 |
| 稳定性 | 批量接收、限长终端缓冲、串口异常和输入格式错误提示 |

终端内容使用约 10 万字符的可视环形窗口；超过容量后按新增量滚动移除最早内容，RX 计数仍记录完整会话接收字节数。该上限用于避免 WinUI TextBox 在超大二进制文本下持续重排而阻塞界面。

## 快速开始

### 使用已发布版本

1. 下载与电脑架构一致的 ZIP。普通 Intel/AMD 64 位电脑选择 `win-x64`。
2. 将 ZIP 完整解压到本地目录，不要只取出 `Comet.exe`。
3. 双击 `Comet.exe`。
4. 选择 COM 端口和通信参数，点击“连接串口”。
5. 从内容区直接键入，或在底部发送框中编辑后点击“发送”。

目标电脑需要 Windows 10 1809 或更高版本，以及串口设备对应的 Windows 驱动；自包含发布版本不需要另外安装 .NET 或 Windows App SDK Runtime。

### 从源代码运行

```powershell
dotnet restore .\Comet.csproj -r win-x64
dotnet run --project .\Comet.csproj -c Debug -p:Platform=x64 -r win-x64
```

## 使用说明

### 连接串口

1. 接入串口设备并安装对应驱动。
2. 点击串口选择框右侧的刷新按钮。
3. 设置波特率、数据位、停止位、校验位、流控制和 DTR/RTS。
4. 选择字符编码并点击“连接串口”。

连接后通信参数会锁定，断开串口后才能修改。底部状态栏会显示当前 COM 端口、连接状态以及 RX/TX 字节数。

### 三种发送方式

#### 内容区键入

连接串口后，在“数据终端”内容区键入或粘贴文字，新增内容会立即编码并发送：

- 键入内容不会由 Comet 写入终端历史，也不会产生本地回显。
- 内容区只显示设备真正返回的 RX 数据；设备开启回显时，才会看到刚刚输入的字符。
- 删除、选择文字、移动光标和复制不会发送数据。
- 粘贴的换行会按当前“行尾”设置发送；当行尾为“无”时，Enter 发送 LF。
- 内容区输入按选定字符编码发送，不解析 `\r`、`\n` 等字面转义序列。

这种方式适合连接 Linux Shell、Bootloader 或命令行固件时进行即时交互。

#### 底部发送框

底部发送框适合在发送前完整编辑内容：

- 文本模式会解析转义字符，并在末尾追加所选行尾。
- HEX 模式发送原始字节，“行尾”设置在 HEX 模式下不生效。
- 点击“发送”或按 `Ctrl+Enter` 发送。
- 开启循环发送后，当前内容会按设定周期重复发送；连接断开或发送失败时自动停止。

文本模式支持以下转义：

| 输入 | 含义 |
| --- | --- |
| `\\` | 反斜杠 |
| `\0` | 空字符 NUL |
| `\a`、`\b`、`\f`、`\v` | BEL、退格、换页、垂直制表 |
| `\t` | 水平制表 |
| `\r`、`\n` | 回车、换行 |
| `\xNN` | 两位十六进制字符，例如 `\x0D` |
| `\uNNNN` | 四位 Unicode 字符，例如 `\u4F60` |

#### 快捷指令

点击数据终端标题栏右侧的列表按钮打开快捷指令面板。初始列表为空，不内置任何设备专用指令。

- 输入名称和指令内容，选择文本或“HEX 发送”模式及行尾后点击“添加”。
- 已添加指令可直接编辑，输入框失去焦点时自动保存。
- “载入”只把预设载入底部发送区，便于继续编辑。
- 箭头按钮立即发送预设，不会覆盖底部发送框。
- 垃圾桶按钮删除对应指令。

快捷指令保存在：

```text
%LocalAppData%\Comet\presets.json
```

### 文本、HEX 与行尾

“HEX 显示”和“HEX 发送”是两个独立选项：

- 开启“HEX 显示”后，当前保留的 RX 内容和后续接收字节都会按 `31 32 33` 格式显示；取消勾选后立即恢复文本显示。
- 开启“HEX 发送”后，底部发送框按原始字节解析，例如 `AA 01 0D 0A`。
- HEX 输入支持空格、Tab、换行、逗号、分号、冒号、短横线和下划线作为分隔符，也支持 `0xAA` 写法。
- HEX 数据必须由完整字节组成；例如 `A` 会被判定为格式错误，应写成 `0A`。
- “无 / CRLF / CR / LF”只会为文本发送追加相应行尾。

### 时间戳和终端显示

| 设置 | 内容区显示行为 |
| --- | --- |
| 时间戳开启 | 显示 `HH:mm:ss.fff`、RX/TX/SYS 标识及内容 |
| 时间戳关闭 | 只显示设备接收内容，不显示 TX 和 SYS 记录 |
| HEX 显示开启 | 已有及后续 RX 数据立即切换为带空格的两位十六进制字节 |
| 自动滚动开启 | 没有选中文字时自动跟随最新内容 |

“时间戳”只影响切换后的新记录，不重新格式化已有内容；“HEX 显示”则会立即切换当前保留的全部 RX 内容，并在取消勾选时恢复接收时解码的文本。TX、SYS、时间戳和换行规则不会因 HEX 切换而改变。选择内容进行多行复制时，程序会保留当前选择，不会强制跳到最底部。

标题栏中的保存按钮会把当前终端内容保存为 UTF-8 `.txt` 文件；清空按钮会同时清除终端内容并将 RX/TX 计数归零。

## 内容区设计与维护规范

本节是后续开发的功能约束和回归测试依据。这里的“内容区”特指 `MainPage.xaml` 中的 `TerminalTextBox`，不包括底部的 `SendTextBox`。修改内容区相关代码时，应保持以下行为；如果确实需要改变，必须同步修改本节和对应验收用例。

### 1. 单一文本控件

- 内容区必须继续使用一个支持多行的 `TextBox`，不得把时间、RX/TX/SYS 标识和正文拆分成多个列表项、文本块或独立列。
- 时间戳、方向和其他前缀必须先拼接为普通文本，再写入同一个内容缓冲。
- 所有可见字符都必须支持原生选择和复制，包括时间、RX/TX/SYS 标识、空格和正文。
- 必须支持任意范围的跨行选择、`Ctrl+C` 和右键复制；选择内容不得引发异常。

详细记录采用以下纯文本格式：

```text
HH:mm:ss.fff  RX   内容
HH:mm:ss.fff  TX   内容
HH:mm:ss.fff  SYS  内容
```

### 2. 数据来源和显示边界

- `RX` 表示串口实际接收到的原始字节，是内容区正文的唯一设备数据来源。
- 每次 RX 必须同时保留原始字节和按接收时字符编码生成的文本，以支持 HEX/文本即时双向切换。
- `TX` 只记录底部发送框、循环发送和快捷指令产生的发送；内容区即时键入不得自行追加 TX 文本。
- `SYS` 只用于连接、断开等终端状态记录，不得伪装成设备返回。
- 内容区键入不存在本地回显。用户看到刚输入的字符，必须是设备通过串口真正回传的 RX 数据。
- 串口未连接时内容区保持只读，但已有内容仍必须可以选择和复制。
- 刷新端口、更新界面、重新渲染、切换选项、选择、删除和移动光标不得产生任何串口发送。

### 3. 时间戳规则

- 开启“时间戳”时，后续 RX、TX 和 SYS 记录显示时间及方向前缀。
- 关闭“时间戳”时，后续只追加 RX 正文；TX 和 SYS 不进入可见文本。
- 时间戳开关只影响切换后的新记录，不得重新格式化、隐藏或补写已有内容。
- 连续 RX 事件是传输分块而不是自然行。相邻 RX 分块必须连续拼接，不得因为一次 `DataReceived` 事件自动插入换行或空白行。
- 文本模式必须保留设备返回的真实 CR/LF，不得显示为 `\r`、`\n` 字面文本，也不得额外制造空白行。

### 4. HEX 显示规则

- “HEX 显示”控制当前保留的全部 RX 数据及后续 RX 数据，与“HEX 发送”完全独立。
- 每个字节必须使用大写两位十六进制，并以一个空格分隔，例如字节 `31 32 33` 不得显示成 `313233`。
- 跨多个接收分块时也必须保留恰好一个字节分隔空格，不得粘连或重复空格。
- HEX 模式按原始字节显示，不解释编码、CR、LF 或其他控制字符。
- 勾选后必须立即把已有 RX 内容切换为 HEX；取消勾选后必须立即恢复接收时解码的文本。
- HEX 切换不得改写 TX、SYS、时间戳状态或记录顺序，也不得产生空白行。
- 文本和 HEX 两种视图必须同步维护限长缓存，切换时不得遍历串口重新读取数据，也不得因大量历史内容产生明显卡顿。

### 5. 内容区键入发送

- 只有串口已连接时才允许内容区键入发送。
- 每个新增字符都应立即按当前字符编码发送；粘贴文本应按一次新增内容发送，不能逐步重写已有终端文本。
- 发送完成后必须取消对内容区文本的实际编辑，保持已有 RX/日志内容不变，等待设备回传形成显示。
- 在已有文本的任意光标位置插入内容时，只发送新增部分，不得重发光标前后的历史内容。
- Backspace、Delete、剪切和替换操作中的删除部分不得发送；替换操作只允许发送真正新增的部分。
- 内容区不解析 `\r`、`\n`、`\xNN` 等字面转义。需要转义解析时应使用底部发送框或快捷指令。
- Enter 和粘贴文本中的换行必须统一处理：行尾为“无”时发送 LF；选择 CR、LF 或 CRLF 时发送对应字节序列。
- TX 计数必须按实际写入串口的字节数增加，不能按 .NET 字符数计算。
- 发送失败必须给出错误提示并刷新连接状态，不能把失败内容留在内容区造成已经发送的假象。

### 6. 渲染、选择和滚动

- `TerminalBuffer` 使用分段环形缓冲同步维护文本和 HEX 两份限长视图，是可见终端文本的来源；UI 文本框只是当前视图的呈现，不得把 `TextBox.Text` 反向当作串口发送缓存。
- 程序内部设置 `TextBox.Text` 时必须处于受保护的渲染状态，绝不能触发键入发送逻辑。
- 断开串口会把内容区切换为只读，但断开提示或最后一批 RX 可能已进入待渲染队列。内部使用 `SelectedText` 做增量更新时必须在 UI 线程内短暂解除只读并立即恢复，不能让只读状态导致 `UnauthorizedAccessException`；页面卸载后不得再执行文本增量或滚动操作。
- 接收数据应先进入线程安全队列，再以低优先级、限时且限量的批次切换到 UI 线程；每批处理后必须让出 UI 线程，禁止持续清空队列导致点击和键入事件饥饿，也禁止在串口回调中直接逐字更新控件。
- 高频数据应合并并增量追加到文本框，禁止每收到一个分块就重建完整可视文本；当前刷新间隔随内容量采用约 50 / 100 / 250 ms 三级节流。正常接收和达到容量上限后的滚动都必须使用“移除前缀 + 追加后缀”的增量更新，只有手动切换 HEX 或清空时允许整框赋值。
- 开启自动滚动且没有选中文字时，新数据到达后必须滚动到最新内容，最后一行应始终可见。
- 关闭自动滚动或存在选择范围时，必须保留当前光标和选择，不能抢占用户正在进行的多行复制。
- 新数据到达时不得导致选择崩溃、选择范围越界或内容区失去复制能力。
- 可视缓冲区维持约 10 万字符滚动上限；到达上限后，新增多少就从头部精确移除多少（HEX 最多额外对齐一个字节），内容量不得突然大段缩水。缓冲层必须通过移动首段偏移或摘除完整旧段实现，禁止扫描、复制或搬移剩余的大段内容。
- 文本模式必须使用跨接收分块保持状态的字符解码器；无法按当前编码解码的随机字节使用单字符 `?` 显示为乱码，不得生成 `\xNN` 转义文本。使用普通单字节字符可避免大量二进制数据因字体回退而阻塞界面。原始 RX 字节仍必须保留给 HEX 显示，切换到 HEX 后应能看到准确字节。
- 进入环形缓冲前必须适配 WinUI TextBox：CR/LF/TAB 保留终端操作语义并正确合并跨分块 CRLF；C0 控制字符使用各自唯一的控制图形（如 NUL `␀`、ESC `␛`），DEL 显示为 `␡`，其他 Unicode 控制字符显示为 `\uNNNN`。原始 RX 字节和 HEX 显示不得因此改变。
- 垂直滚动条必须持续可用；容量滚动不得重建 `TextBox`、重置内部滚动布局或导致滚动条消失。
- 内容区必须按当前可用宽度进行视觉自动换行，即使数据中没有 CR/LF，超长文本或二进制显示也要在窗口边缘折行；窗口宽度变化后由控件重新排版。视觉折行不得向缓冲区或保存日志中插入真实换行字符，不得改变复制结果、RX 字节、HEX 数据或计数。内容区不使用水平滚动条；自动滚动开启时跟随最底端。

### 7. 清空和日志

- 清空操作必须同时清除终端缓冲、可见文本、历史记录以及 RX/TX 计数。
- 清空后应恢复“等待串口数据”空状态，不得影响当前串口连接。
- 保存日志必须保存当前内容区可见的完整纯文本，保持时间戳、方向前缀、HEX 空格和真实换行。
- 日志使用 UTF-8 编码；保存操作不得暂停、修改或重新格式化当前终端内容。

| T02 | 无回环时在内容区键入 `help` | 内容区不显示本地输入，TX 增加 4 字节 |

| T04 | 行尾依次选择无、CR、LF、CRLF 后按 Enter | 分别发送 `0A`、`0D`、`0A`、`0D 0A`，TX 计数与字节数一致 |

| T10 | 连续接收不带换行的多个分块 | 文本内容连续、HEX 字节以单空格连接；两种模式都没有额外空行 |
| T11 | 跨多行选择并复制，同时继续接收或切换 HEX | 选择范围安全收敛、不崩溃，复制结果包含当前视图的前缀和正文 |

| T13 | 选择、删除、移动光标、程序刷新或切换 HEX | 串口没有任何意外下发，TX 计数不增加 |
| T14 | 清空终端 | 文本/HEX 缓冲和 RX/TX 计数清零，串口仍保持原连接状态 |
| T15 | 高速接收并反复切换 HEX，直至并持续超过容量上限；期间点击发送框、快捷指令输入框并选择多行内容 | UI 保持可操作，各输入框可立即获得焦点，选择不崩溃；内容量稳定在滚动上限附近，不得突然缩水；最旧内容按新增量滚动移除，垂直滚动条始终存在 |
| T16 | 非 HEX 模式接收包含任意字节、分块 UTF-8、NUL、ESC、BEL、CR/LF/TAB 的二进制流 | 有效文本正常解码；无法解码的序列显示为单字符 `?`，不出现 `\xNN` 转义；控制字符使用唯一可见符号，CR/LF/TAB 执行终端操作；内容不得在 NUL 处截断或变空，HEX 显示仍保留准确原始字节 |
| T17 | 使用真实设备连续接收 2–3 MB 图像数据 | RX 累计完整字节数，可视环形窗口稳定在约 10 万字符，文本/HEX 可双向切换，垂直滚动条保持可用，传输期间输入框和多行选择保持响应 |
| T18 | 连续运行 10 分钟并周期性触发大数据返回 | 全程无“未响应”，输入区域始终可聚焦；RX 持续累计，可见窗口只淘汰最旧分段，内存和句柄数保持在稳定范围内 |
| T19 | 接收一条不含 CR/LF 且宽度超过内容区的长数据，并反复缩放窗口 | 内容按当前窗口宽度视觉折行且随宽度重新排版；水平滚动条不出现，复制和保存得到的原始逻辑文本中没有额外换行 |
| T20 | 连接串口后立即断开，或在 RX 数据和终端渲染尚未完成时断开；重复执行至少 20 次 | 程序不崩溃，不出现 `UnauthorizedAccessException`；断开后内容区恢复只读并仍可选择复制，最后一批已接收数据和断开提示可安全完成渲染 |

推荐使用 USB 转串口模块将 TX 与 RX 短接进行物理回环测试；测试期间确认没有其他串口工具占用同一 COM 端口。至少保留文本、HEX、时间戳切换、选择复制、自动滚动和意外发送检查的测试结果。

### 2026-08-24 视觉自动换行回归结果

在 COM5 接收 450.30 KB 图像数据后，可见文本稳定为 100,000 字符。抽检时逻辑文本包含 0 个 CR、0 个 LF，但内容区只有启用的垂直滚动条且没有水平滚动条，证明长逻辑行按可用宽度进行了视觉折行。窗口最大化再还原时，内容区宽度由 572 px 变为 1,228 px 后恢复为 572 px，应用全程保持响应；切换 HEX 后字节间仍有单空格，切回文本后 100,000 字符逐字一致。

### 2026-08-24 随机二进制文本回归结果

## 打包发布

当前推荐发布方式是 `Unpackaged + self-contained`。交付物为可直接解压运行的完整目录，不是需要注册和签名的 MSIX 安装包。

### 1. 构建 Release x64

```powershell
dotnet restore .\Comet.csproj -r win-x64
dotnet build .\Comet.csproj -c Release -p:Platform=x64 -r win-x64 --self-contained true --no-restore
```

可交付目录：

```text
bin\x64\Release\net10.0-windows10.0.26100.0\win-x64\
```

该目录必须包含 `Comet.exe`、`App.xbf`、`MainPage.xbf`、`MainWindow.xbf`、`Assets` 目录以及全部 DLL。不要只复制 EXE。

> 当前 Unpackaged WinUI 3 工程应使用上述 Release 构建目录作为发布源，不要分发缺少 `.xbf` 和 `Assets` 的独立 `publish` 子目录，也不要使用仓库中旧的 Debug MSIX 测试包。

### 2. 压缩发布目录

```powershell
$releaseDir = Resolve-Path '.\bin\x64\Release\net10.0-windows10.0.26100.0\win-x64'
$archiveDir = Join-Path $PWD 'artifacts'
$archive = Join-Path $archiveDir 'Comet-win-x64.zip'
New-Item -ItemType Directory -Path $archiveDir -Force | Out-Null
Compress-Archive -Path (Join-Path $releaseDir '*') -DestinationPath $archive -Force
```

输出文件为 `artifacts\Comet-win-x64.zip`。在目标电脑上完整解压后运行 `Comet.exe`。

### 3. 其他处理器架构

| 目标电脑 | Platform | Runtime Identifier | Release 输出目录前缀 |
| --- | --- | --- | --- |
| 常规 64 位 Intel/AMD | `x64` | `win-x64` | `bin\x64\Release` |
| 旧式 32 位 Windows | `x86` | `win-x86` | `bin\x86\Release` |
| Windows on ARM | `ARM64` | `win-arm64` | `bin\ARM64\Release` |

例如构建 ARM64：

```powershell
dotnet restore .\Comet.csproj -r win-arm64
dotnet build .\Comet.csproj -c Release -p:Platform=ARM64 -r win-arm64 --self-contained true --no-restore
```

### 4. 发布前检查

- 从 Release 输出目录启动一次 `Comet.exe`。
- 确认主界面、任务栏图标、串口刷新和快捷指令面板正常。
- 检查 `Comet.exe`、三个 `.xbf` 文件、`Assets` 目录及 DLL 是否齐全。
- 在目标架构的干净电脑上解压测试，确认不需要额外运行库。
- 使用串口回环或测试设备检查文本、HEX、行尾、时间戳、复制和 RX/TX 计数。

自包含 WinUI 版本包含 .NET 和 Windows App SDK 运行文件，因此压缩前目录体积较大是正常现象。项目有意关闭程序集裁剪，避免 WinUI/WinRT 和 JSON 运行时元数据在 Release 版本中被误删。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 找不到 COM 端口 | 检查 USB 线、设备供电和 USB 转串口驱动，然后点击刷新按钮 |
| 提示拒绝访问或端口被占用 | 关闭 MobaXterm、PuTTY、其他串口助手或另一个 Comet 实例，同一串口通常只能被一个程序占用 |
| 收到乱码 | 核对波特率、数据位、校验位、停止位和字符编码；设备输出非文本数据时开启 HEX 显示 |
| 在内容区输入后文字不保留 | 这是终端即时发送的预期行为；内容区只显示设备 RX 回传，需要编辑完整命令时使用底部发送框 |
| 输入 `\r` 后设备没有换行 | 内容区不会解析字面转义；请在底部发送框中使用 `\r`，或选择 CR/CRLF 行尾 |
| 时间戳切换后旧内容没变化 | 这是预期行为，时间戳只影响后续记录；HEX 显示应立即切换当前保留的 RX 内容 |
| 出现 `DEP0700` | 不要部署或注册旧 MSIX；选择 `Comet` 项目并直接启动 Unpackaged 配置 |
| Release 中只有 EXE，程序无法启动 | 必须复制或压缩整个 Release 输出目录，确认 `.xbf`、`Assets` 和 DLL 完整 |
| Windows 显示未知发布者 | 当前便携版本未签名；内部使用可确认来源后运行，对外发布建议配置代码签名 |

## 本地数据与隐私

- 快捷指令只保存在 `%LocalAppData%\Comet\presets.json`。
- 日志只写入用户在保存对话框中选择的位置。
- 串口数据在本机处理，应用本身不需要账户，也不会主动上传终端内容。

删除 `%LocalAppData%\Comet\presets.json` 可重置快捷指令；请先退出 Comet，避免退出或编辑时再次写入。
